nothing it doesn't

Each module is purpose-built for one thing. No configuration files, no hidden defaults.

🧹

Data Cleaning

Automated quality fixes that prevent silent model failures downstream.

  • Mean / Median / Mode imputation per column
  • IQR outlier detection — cap or remove
  • Duplicate row identification & removal
  • String whitespace normalization
📊

EDA Visualizations

Understand your data's shape before you touch a model.

  • Histograms + KDE for all numeric columns
  • Bar charts for top-10 categorical values
  • Correlation heatmap with coolwarm palette
  • Base64-embedded — no external image hosting
⚙️

Feature Engineering

Standard transformations, selectively applied to the columns you choose.

  • LabelEncoder for categorical string columns
  • StandardScaler — normalises to Mean=0, Std=1
  • Column-level checkbox selection in the UI
  • Applied in-memory — no file I/O overhead
🤖

Model Training

Three problem types, five algorithms, one consistent interface.

  • Classification: Logistic Regression, Random Forest
  • Regression: Linear Regression, Decision Tree
  • Clustering: K-Means (k=3, auto init)
  • Automatic 80/20 train-test split
📈

Model Evaluation

Clear metrics with context — colour-coded so you know if a result is good.

  • Classification: accuracy_score()
  • Regression: r2_score() and RMSE
  • Clustering: silhouette_score()
  • Green ≥ 80%, amber 60–80%, neutral below
💾

Model Export

One click to download a file you can load in any Python script.

  • Serialised with joblib.dump() → .pkl format
  • Load anywhere with joblib.load()
  • Served as a Flask streaming file download
  • No cloud storage or third-party services

About PipelineX AI

Industrial Training Project · 2026 · Built by Shivang Verma & Utkarsh Verma

What is PipelineX AI?

PipelineX AI is a web-based machine learning automation platform that guides users through the complete ML lifecycle — from raw dataset upload to a downloadable trained model — without writing a single line of code.

It was built for students, researchers, and practitioners who want to prototype ML workflows quickly, understand what each pipeline stage does, and eliminate the repetitive boilerplate that clutters notebooks and scripts.

Why it was built

Every ML project starts the same way: load data, check for missing values, visualize distributions, encode categoricals, scale numerics, split data, train, evaluate, export. This work is real, necessary, and almost entirely identical across projects. PipelineX encodes this best-practice workflow into a guided web interface so you can focus on decisions that actually matter — which features to use, which algorithm to try, how to interpret your results.

The pipeline — 8 modules

  • Module 2–3: File upload and multi-format parsing (CSV, Excel, JSON, XML, HTML)
  • Module 4: Dataset summary — shape, dtypes, missing value analysis, descriptive statistics
  • Module 5: EDA — histograms, bar charts, correlation heatmap (matplotlib + seaborn)
  • Module 6–8: Data cleaning — imputation, IQR outlier handling, duplicate removal
  • Module 9: Feature engineering — LabelEncoder, StandardScaler, selective column application
  • Module 10: Problem selection — Classification, Regression, or Clustering + target column
  • Module 11–13: Algorithm selection, training (80/20 split), evaluation (Accuracy / R² / RMSE / Silhouette)
  • Module 14: Model export — serialized with joblib.dump() to .pkl, served as file download

Privacy Policy

Effective: March 1, 2026 · Last updated: April 2026

This Privacy Policy explains what information PipelineX AI collects, how it is used, and your rights regarding that information.

1. Information we collect

Account data: When you register, we collect your full name, email address, and a hashed version of your password. Your password is never stored in plaintext — it is hashed using Werkzeug's generate_password_hash() before being written to the database.

Uploaded datasets: Files you upload are temporarily stored in a local uploads/ directory during your session. The parsed DataFrame is held in server memory. We do not permanently store, analyse, or share your data.

Session data: We use server-side Flask sessions to maintain your login state and transient pipeline state (filename, problem type, algorithm). This data is cleared on logout.

2. How we use your information

  • To authenticate you and maintain your session
  • To process your uploaded dataset through the ML pipeline
  • To serve visualizations and trained model files back to you

We do not use your data for advertising, profiling, or analytics of any kind.

3. Data retention

Uploaded files are not guaranteed to persist beyond your session. Account data (name, email, hashed password) is stored in a local SQLite database (users.db) and retained until you request deletion.

4. Cookies

We use a single session cookie to maintain your login state. No tracking or analytics cookies are set. Disabling cookies will prevent login from functioning.

5. Third-party services

PipelineX AI does not share your data with any third parties. Google Fonts is used for typography — your browser may request font files from Google's CDN.

6. Security

Passwords are stored as salted hashes. Sessions are signed with a server-side secret key. This is an educational project and is not hardened for production security — do not upload sensitive or confidential datasets.

7. Your rights

You may request deletion of your account and data at any time by opening an issue at github.com/Shivangverma7.
